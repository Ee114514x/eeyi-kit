# Eeyi 深度手册（按需读，不常驻）

技能正文只放“会做错事”的硬约束；本文件放工作流、后处理与完整坑位。
本文件随源码分发，`install` 不复制它——不存在时忽略，技能正文不依赖它。

---

## 1. 调用契约

- stdout 是内容，stderr 是统计；管道只读 stdout。
- `trim` 输出只做定位参考；精确阅读、逐字修改必须回原文。
- `count` 是按字数比例的估算，已用 GPT-4/4o 分词器实测校准（中文密集文本误差约 ±10%，代码/JSON 约 ±30%）；Claude、DeepSeek 等其它 tokenizer 会再差 ±30%，只宜做相对比较。
- 参数名一律用 ASCII 连字符（`--max-lines`），不要用 U+2011 等排版连字符，否则 argparse 直接报 `unrecognized arguments`。

## 1b. install 到底做什么

1. 把 `eeyi.py` 复制到 `<scope>/Eeyi/eeyi.py`。
2. 用脚本内置的 `SKILL_TEMPLATE` 生成 `<scope>/Eeyi/SKILL.md`，把 `{{EEYI}}` 替换成副本的绝对路径。
3. **不复制** `GUIDE.md`、`verify_*.py`——它们只随源码分发。
4. 可重复执行（幂等）；但改了源码必须重新 install，否则技能目录里仍是旧副本。
5. 默认 scope 从当前目录向上找最近的 `.aicode`，找不到才用 `~/.aicode/skills`。

## 2. 工作流：先估算再压缩，最多迭代 2 次

1. `count <文件>` 估算输入体积。
2. 按需要设 `trim --max-lines`（默认 80）。压缩后 token 仍明显过高，才考虑下调。
3. **最多迭代 2 次**。每次迭代都要重传原始输入，在 Agent 里等于把同一份日志反复塞进上下文，省下的会被吃回来。
4. 只在首次输出超过预期 3 倍时才调参；否则直接用结果。

## 3. 参数策略

| 子命令 | 参数 | 默认 | 作用 |
|---|---|---|---|
| trim | `--max-lines` | 80 | 输出总行数预算（堆栈块、摘要、标记不计入） |
| trim | `--head` / `--tail` | 12 / 12 | 头尾各保留多少行 |
| trim | `--max-col` | 300 | 单行超过多少字符时中部截断（最小 4） |
| trim | `--min-repeat` | 3 | 连续相同行达到几次才折叠（最小 2） |
| trim | `--max-period` | 16 | 周期块最大长度，超过就退化按单行重复处理 |
| trim | `--keep-all-errors` | 关 | 错误行完全不丢弃，只折叠同类 |
| digest | `--depth` | 1 | 目录递归深度 |
| digest | `--max-entries` | 60 | 目录最多列多少个文件 |
| digest | `--max-symbols` | 40 | 每个文件最多列多少个符号 |
| json | `--max-keys` | 12 | 每个对象最多展开多少个键（最小 1） |
| json | `--max-str` | 60 | 字符串截断宽度，内部再限 40（最小 4） |
| count | 无 | — | 接一个或多个文件 |
| install | `--scope` | 向上找 `.aicode`，否则 `~/.aicode/skills` | 目标技能目录 |
| bench | `--corpus` | 自动找 `dsh-ops` | 代码语料目录 |

默认值多数场景不用改；`--head/--tail/--max-col` 只在输出仍偏长或关键行被截时手动调。

### 参数策略

- 长流水日志：默认参数即可。
- 需要每一条错误都留下：加 `--keep-all-errors`（token 会明显上涨，输出可能很大）。
- 只想看错误概览：`trim` 后丢弃普通 INFO 行，保留 `<首个错误>`、堆栈、`<错误位置>`。
- 大 JSON：优先 `json <文件>`，不要把原始 JSON 喂进上下文。
- 目录概览：`digest <目录> --depth 1`；少于 150 行的文件直接读全文，别用 digest。

## 4. 读输出的坑（每条都有可执行取证）

| 编号 | 事实 | 应对 |
|---|---|---|
| C1 | `<首个错误：第 N 行>`、`<同类 M 条：第 x-y 行>` 的行号来自**折叠后的中间序列**，既非原文行号也非输出行号 | 不要用它回查原文；回原文只按 `<错误位置：文件:行号>` |
| C1 | `<错误位置：…>` 是正则从错误行里抓的，可能抓到日志顺带提到的无关路径 | 用它之后确认该路径属于本次故障 |
| C2 | 摘要行不是原文内容；折叠后行数没超预算时摘要**不出现** | 没看到摘要不等于没有错误 |
| C3 | 输出常略超 `--max-lines`（摘要、标记、同类说明不计入预算） | 超了不是出错，不要反复调参 |
| C4 | git diff 不做行数截断，但**会被改写**（重复 context 折叠、长行中部截断、空行合并） | 要可应用的补丁就读原文，不要用 trim 结果打补丁 |
| C5 | diff 的长行会被中部截断 | 同上 |
| C6 | diff 的 `+`/`-` 行与 hunk 头不会整行丢失 | 但仍不等于逐字一致 |
| C7 | 堆栈块整块保留，判定偏宽：块后紧跟的缩进行会被纳入 | 块内非异常行不要当根因 |
| C8 | 自定义异常名（不是 `*Error`/`*Exception`/`panic:`）不会进块，摘要可能落到源码行 | 摘要里看到 `raise …` 就说明异常行未被识别，回原文 |
| C9 | 错误位置可能抓到无关路径 | 同 C1 |
| C10 | `--keep-all-errors` 时错误行零丢失 | 需要全量时用它 |
| C11 | 同类错误按签名归并，标出 `<同类 N 条>` 与未列出的类型数 | 看类型数判断是否还有没展示的错误类别 |
| C12 | 类型超预算时按 fatal > error > warning 优先 | warning 洪流不会挤掉 fatal |
| C13 | json 里长值（含 base64）被截成前 40 字符，只是残片 | 不要据此推断内容；要具体值回原文指定 key |
| C14 | 所有 `<…>` 标记处都不是原文连续内容 | 精确字节、拼写、缩进一律回原文 |
| C15 | digest 是正则启发式，函数体、模块常量会丢失 | 关键文件读全文 |
| C16 | 长堆栈截断会把断点对齐到栈帧起始行 | 片段起点是 `File`/`at` 行，续行不会孤立出现 |
| C17 | 长堆栈截断已对齐栈帧（块 42 行 → 22 行）；达到 80 行上限被截断时，缩进区之后的异常行会单独保留并进入摘要 | 需要完整调用链时读原文；`--keep-all-errors` 不影响堆栈截断 |

## 5. 后处理补偿（脚本能力之外，由调用方补）

- 模板相同、只有数字/时间/uuid 不同的**非错误**行不会被折叠：识别后保留首末样例，其余标注“模板重复”。
- 需要结构化结果时，从输出中提取 `<首个错误>`、`<错误位置>`、`<同类 N 条>`、`<另有 X 类>`，整理成简短笔记，而不是保留全文。
- 疑似 base64 / 长哈希字段不要展开，回原文按 key 取值。
- 只要 schema 不要样本时，`--max-keys` 调小即可，不必手工删行。

## 6. 调用模板

```bash
# 普通 CI 日志
<cmd> 2>&1 | python3 eeyi.py trim

# 需要每条错误
<cmd> 2>&1 | python3 eeyi.py trim --keep-all-errors

# 大 JSON 字段结构
python3 eeyi.py json big.json

# 目录概览
python3 eeyi.py digest . --depth 1

# 体积估算
python3 eeyi.py count app.log
```

## 7. 禁止行为

1. 使用者不要改 `eeyi.py` 来补功能；需要新行为就用参数组合与后处理。
2. 不要把 `trim` 对 diff 的输出当补丁。
3. 堆栈疑似被截断时，**不要靠调大 `--max-lines`**——堆栈块不受该参数约束，调它无效；应直接读原文的栈帧区间。
4. 不要用 `<首个错误：第 N 行>` 的行号去原文定位。
